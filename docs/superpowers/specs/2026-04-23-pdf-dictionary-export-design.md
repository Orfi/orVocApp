# PDF Dictionary Export — Design Spec

## Overview

Export the user's vocabulary list as a printer-friendly PDF dictionary combining English definitions, phonetics, examples, and Arabic translations. The PDF uses a spacious dictionary layout with color-coded alphabetical letter tabs for easy navigation when printed.

## Architecture

### Class Hierarchy

```
BaseExporter (abstract, QObject)
├── PdfExporter
└── (future) EpubExporter, etc.
```

**BaseExporter** owns the shared export pipeline:

- Takes the word list from `VocabManager::words()`
- Runs on a `QThread` with its own `QNetworkAccessManager` (Qt requires QNAM on the thread that uses it)
- Fetches definitions and translations sequentially for each word using the same API endpoints as `NetworkClient` (`dictionaryapi.dev` and Google Translate GTX)
- Reuses `NetworkClient::parseDictionaryResponse()` and `NetworkClient::parseTranslationResponse()` static methods to parse responses
- Stores results in a `QVector<WordEntry>`
- Emits `progress(int current, int total)` and `finished(bool success, const QString &filePath)` signals (delivered to QML main thread via queued connections)
- Declares pure virtual `renderToFile(const QVector<WordEntry> &entries, const QString &outputPath) -> bool`
- Provides `exportToFile(const QString &outputPath)` which orchestrates: fetch all words → filter valid entries → call `renderToFile()`

**PdfExporter** subclass implements `renderToFile()` using `QPrinter` + `QPainter` + `QTextDocument`. Accepts page size (A4 or Letter) as a constructor parameter.

### Data Model

```cpp
struct WordEntry {
    QString word;
    QString phonetic;
    QString definitionHtml;   // full HTML from parseDictionaryResponse
    QString translationHtml;  // RTL HTML from parseTranslationResponse
    bool valid;               // false if either API call failed — entry is skipped
};
```

## PDF Rendering Pipeline

`PdfExporter::renderToFile()` proceeds in this order:

### 1. Setup

Configure `QPrinter` with `PdfFormat`, user-selected page size (A4 or Letter), portrait orientation, ~20mm margins.

### 2. Cover Page

Drawn with `QPainter`:

- Rainbow gradient decorative lines at top and bottom of the page
- "orVocApp" title centered, large and bold
- "Personal Dictionary" subtitle in italics
- Word count and generation date below a thin divider
- Then `QPrinter::newPage()`

### 3. Group Entries by Letter

Entries are already sorted alphabetically from `VocabManager`. Group into letter sections (A, B, C...).

### 4. Render Letter Sections

For each letter section:

- Start a new page for each new letter
- **Page header** (every page in the section, not just the first): "orVocApp Dictionary" left-aligned, colored letter tab top-right corner
- For each word entry, build an HTML block containing:
  - Word in bold, large font
  - Phonetic transcription in smaller gray text
  - All definitions grouped by part of speech (uppercase label + definition text)
  - Examples in italics where available
  - Arabic translation in a light gray (#f8f8f8) bordered box, right-aligned RTL
- Render each entry via `QTextDocument::drawContents()` through `QPainter`, tracking Y position on the page
- When remaining page space is insufficient for the next entry: `newPage()` and redraw the page header with the same letter's color tab

### 5. Page Footer

Every page except the cover: "Generated by orVocApp" left-aligned, page number right-aligned.

### Color-Coded Letter Tabs

Each letter gets a unique color computed from a full rainbow hue rotation:

```cpp
QColor letterColor(int letterIndex) {
    qreal hue = (letterIndex / 26.0) * 360.0;
    return QColor::fromHsv(static_cast<int>(hue), 200, 200);
}
```

The tab is drawn as a filled rounded rectangle in the top-right corner of the page header with the letter character in white.

## Print-Friendly Design

- White background, black text
- Arabic translation in a light gray (#f8f8f8) bordered box (no dark backgrounds)
- Blue accent used only for the part-of-speech left border — prints well in both color and grayscale
- Letter tab colors are the only heavy color usage, and they remain distinguishable in grayscale
- Serif font (e.g., Georgia or Times) for readability in print

## User Interaction Flow

1. User clicks **"Export PDF"** button in the toolbar (alongside existing import/export buttons)
2. **Page size dialog** appears — user selects **A4** or **Letter**
3. **File save dialog** opens — save mode, `.pdf` filter, default filename `orvocapp-dictionary.pdf`
4. Export starts — `PdfExporter` created, `exportToFile()` called on worker thread
5. **Progress overlay** appears at bottom-right corner: `ProgressBar` + "Exporting... 12/108 words"
6. User can continue using the app while export runs in the background
7. On completion:
   - Progress bar fades out (300ms opacity animation)
   - After fully invisible: notification text fades in (300ms)
   - Success: green "PDF exported successfully" — stays 4 seconds, then fades out (300ms)
   - Failure: red "Export failed" — stays 4 seconds, then fades out (300ms)

## Error Handling

- Words that fail definition or translation API calls are silently skipped (not included in the PDF)
- Network errors during batch fetch do not abort the entire export — each word is attempted independently
- If all words fail, the export is considered failed and the failure notification is shown

## Threading Model

- `BaseExporter` inherits `QObject` and uses the worker object pattern: creates a `QThread`, moves itself to it, and begins work via a slot connected to `QThread::started`
- `QNetworkAccessManager` is created in the worker slot after the move (Qt requirement: QNAM must live on the thread that uses it)
- `progress()` and `finished()` signals are emitted from the worker thread — Qt's queued connections deliver them to the QML main thread safely
- On completion, the thread is cleaned up

## Future Extensibility

Adding a new export format (e.g., EPUB3 for Kindle):

1. Create `epubexporter.h/.cpp` subclass of `BaseExporter`
2. Implement `renderToFile()` targeting EPUB3/XHTML output
3. Add a new toolbar button or extend the export dialog with format selection
4. All data fetching, threading, and progress reporting are inherited from `BaseExporter`
